Drive 動画プレイヤー 実装解説

Google Drive 上の動画をサムネイル付き一覧から再生する Android アプリ / Kotlin + Jetpack Compose + Media3

1. アプリの全体像

選択した Google Drive フォルダ内の .mp4 を日付ごとの一覧で表示し、 タップするとアプリ専用ストレージにダウンロードしてから再生するアプリです。 ダウンロード済みの動画はオフラインでも即座に再生でき、キャッシュは LRU (最終再生日時が古い順)で自動削除されます。バックグラウンド再生に対応し、 通知・ロック画面から操作できます。

画面役割
サインインGoogle アカウントで drive.readonly の許可を取得(初回のみ。以降はサイレント)
フォルダ選択マイドライブをブラウズして動画フォルダを選択。選択は永続化
動画一覧日付グルーピング+サムネイル+キャッシュ済みマーク。エラー時は再試行導線
再生ダウンロード進捗 → 全画面プレイヤー(再生/一時停止/シーク)
設定フォルダ変更・容量上限・保持期間・モバイル回線許可・使用量表示・全削除

2. モジュール構成(レイヤー)

ui/        画面(Compose)+ ViewModel。状態は StateFlow で保持
domain/    純粋ロジック: 日付グルーピング / サムネイル紐付け / LRU 削除判定
data/      source(動画ソース抽象化+Drive 実装)、cache(Room+ダウンロード)、settings(DataStore)
auth/      AuthorizationClient によるトークン管理
playback/  MediaSessionService(バックグラウンド再生)

「動画ソース」の抽象化

一覧取得・サムネイル取得・動画ダウンロードは VideoSource インターフェースに 分離されています。現在の実装は DriveVideoSource のみですが、将来ローカルフォルダや 他のクラウドをソースとして追加する場合も、UI・キャッシュ層は変更不要です。

interface VideoSource {
    suspend fun listVideos(folderId: String): List<VideoItem>
    suspend fun getThumbnail(item: VideoItem): File?
    suspend fun downloadVideo(item, destination, onProgress)
}

Drive API 呼び出し自体も DriveApiClient インターフェースで分離しており、 ユニットテストでモックできます。公式 Java クライアントは使わず、OkHttp で files.list / files.get?alt=media を直接呼んでいます(依存が軽い)。

3. 認証フロー

起動 → AuthorizationClient.authorize()(UI なし)
├ 許可済み → アクセストークン取得 → そのまま一覧へ(サイレント認証)
└ 未許可 → サインイン画面 → ボタン押下 → Google の同意画面 → トークン取得

AuthorizationClient は Google Cloud Console に登録した「Android 用 OAuth クライアント ID (パッケージ名+SHA-1)」で自動的に解決されるため、クライアント ID をアプリに埋め込む必要が ありません。API 呼び出しが 401 を返した場合はトークンを破棄して 1 回だけ再取得・リトライし、 それでも失敗すればサインイン画面に誘導します。

Web アプリケーション用クライアント ID を local.properties の google.webClientId に設定すると、サインイン時に Credential Manager の アカウント選択シートが先に表示されます(未設定でも機能に影響なし)。

4. 一覧表示とサムネイル

ファイル名は 20260315_タイトル.mp4 のように先頭 8 桁が日付です。 正規表現 ^(\d{8})_ で抜き出し、ResolverStyle.STRICT で 厳密にパースするため「13月」「2月30日」などは弾かれて「日付不明」グループ(末尾)に入ります。 グループは日付降順、グループ内はファイル名昇順です。

サムネイルは同フォルダの同名 .webp を優先し、なければ Drive が生成する thumbnailLink を使います。どちらも取得後は cacheDir/thumbs/ に 保存され、2 回目以降は通信しません。

5. ダウンロードとキャッシュ管理

動画は files/video_cache/<fileId>.mp4 にダウンロードされます。 途中キャンセル・失敗時に壊れたファイルが残らないよう、いったん .part に書いて 完了後にリネームします。メタデータ(fileId・ファイル名・サイズ・最終再生日時)は Room の cached_videos テーブルで管理します。

LRU 削除(CacheEvictionPolicy)

  1. 保持期間切れ: 最終再生から設定日数(既定 30 日)を過ぎたものを起動時に削除
  2. 容量超過: 合計が上限(既定 10GB)を超えたら、最終再生日時の古い順に上限を下回るまで削除
  3. 再生中のファイルは常に除外(PlaybackTracker が再生中 fileId を保持)

この判定は純粋関数として実装され、8 ケースのユニットテストで検証済みです。 実行タイミングは「起動時」「ダウンロード完了後」「設定変更後」の 3 箇所です。

通信量への配慮

既定では非従量制ネットワーク(Wi-Fi 等)のときだけダウンロードします。判定は NET_CAPABILITY_NOT_METERED で行うため、従量制の Wi-Fi テザリングも ブロックされます。設定で「モバイル回線でもダウンロード」を有効にできます。

6. 再生とバックグラウンド再生

再生は Media3 で行います。ExoPlayer は PlaybackService (MediaSessionService)内に生成され、画面側は MediaController 経由で接続します。 この構成により:

  • ホーム画面へ移動・画面オフでも音声再生が継続(フォアグラウンドサービス)
  • 通知とロック画面に再生/一時停止(Media3 標準)+停止(カスタムコマンド)を表示
  • イヤホンを抜くと自動一時停止、オーディオフォーカスも自動処理

再生画面は全画面(システムバー非表示)で、PlayerView の標準コントロール (再生/一時停止・シークバー)を使います。再生画面から「戻る」と再生は停止します。
