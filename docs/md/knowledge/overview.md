## アプリの全体像

選んだ Google Drive のフォルダの配下(サブフォルダを再帰的に含む)にある `.mp4` を、月ごとのサムネイルのグリッド(YouTube 風)で表示し、タップするとすぐにストリーミング再生を始めるアプリです。再生と並行して動画全体をバックグラウンドでアプリ専用ストレージに保存するので、保存済みの動画はオフラインでも再生できます。キャッシュは LRU(最終再生日時の古い順)で自動的に削除されます。バックグラウンド再生に対応し、通知とロック画面から操作できます。

| 画面 | 役割 |
|---|---|
| サインイン | Google アカウントで drive.readonly の許可を取る(初回だけ。以降はサイレント) |
| フォルダ選択 | マイドライブをブラウズして動画のフォルダを選ぶ。複数選べて、選択は永続化する |
| 動画一覧タブ | 月ごとのサムネイルのグリッドと保存済みの印、ディレクトリフィルター。エラーや 0 件のときは再試行とフォルダ変更の導線を出す |
| プレイリストタブ | プレイリストの一覧と中身。カードの長押しで追加する |
| 保存済みタブ | 保存を終えた動画の一覧。端末内のメタデータから表示するので、オフラインでも見られる |
| 再生 | すぐにストリーミング再生し、保存の進捗を表示する。横型は概要欄つき、縦型(shorts)は全画面で表示する |
| 設定 | 対象フォルダの追加と削除、容量の上限、保持期間、モバイル回線の許可、使用量の表示、全削除 |
: 画面と役割

## モジュール構成

```
ui/        画面(Compose)と ViewModel。状態は StateFlow で持つ
domain/    純粋なロジック: 日付のグループ分け、サムネイルの紐付け、フォルダの配下判定、分類、LRU の削除判定
data/      source(動画ソースの抽象化と Drive の実装、一覧のキャッシュ)、cache(Room と保存)、playlist(Room)、settings(DataStore)
auth/      AuthorizationClient によるトークンの管理
playback/  MediaSessionService(バックグラウンド再生)
```

### 動画ソースの抽象化

一覧の取得、サムネイルの取得、再生用の URI は、`VideoSource` インターフェースに分けてあります。今の実装は `DriveVideoSource` だけですが、ローカルフォルダやほかのクラウドをソースとして足すことになっても、UI とキャッシュの層は変えずに済みます。

```kotlin
interface VideoSource {
    suspend fun listVideos(folders: List<VideoFolder>): List<VideoItem>
    suspend fun getThumbnail(item: VideoItem): File?
    fun playbackUri(item: VideoItem): String
}
```

Drive API の呼び出しも `DriveApiClient` インターフェースで分けてあり、ユニットテストではフェイクに差し替えられます。公式の Java クライアントは使わず、OkHttp で `files.list` と `files.get?alt=media` を直接呼んでいます(依存が軽いため)。

## 認証フロー

```
起動 → AuthorizationClient.authorize()(UI なし)
  ├ 許可済み → アクセストークンを取得 → そのまま一覧へ(サイレント認証)
  └ 未許可 → サインイン画面 → ボタンを押す → Google の同意画面 → トークンを取得
```

AuthorizationClient は、Google Cloud Console に登録した「Android 用 OAuth クライアント ID(パッケージ名 + SHA-1)」で自動的に解決されます。そのため、クライアント ID をアプリに埋め込む必要はありません。API の呼び出しが 401 を返した場合は、トークンを破棄して 1 回だけ取り直して再試行し、それでも失敗すればサインイン画面に誘導します。

Web アプリケーション用のクライアント ID を `local.properties` の `google.webClientId` に設定すると、サインインのときに Credential Manager のアカウント選択シートが先に表示されます(設定しなくても機能には影響しません)。Google Cloud 側のリソースの確認と整理は、[Google Cloud のリソースの確認と整理](../how-to/google-cloud-resources.md) にまとめてあります。

## 一覧表示とサムネイル

### サブフォルダの再帰列挙

動画と `.webp` は動画ごとのサブディレクトリにまとめて保存されている想定です。Drive API には「フォルダ配下すべて」をサーバーの側で絞る手段がありません。そこで、全フォルダの一覧と全動画・webp の一覧を一括で取得し、クライアントの側で親子関係を辿って、選択フォルダの配下だけに絞ります(`DriveFolderTree`)。サブフォルダが 1,000 個以上あっても、ページングを含めて数回のリクエストで済みます。2 つの一括取得は並列に投げ、並び順はアプリの側で決めるので `orderBy` は付けません。

### 前回の一覧をすぐに表示する

一括取得はドライブ全体が対象なので、動画が多いと数秒かかります。そこで最後に取得した一覧を `cacheDir/video_list.json` に保存しておき(`VideoListCache`)、次回はそれをすぐに表示してから、裏で最新を取得して差し替えます(stale-while-revalidate)。取得中は画面の上部に細いプログレスバーが出ます。取得に失敗しても一覧は消えず、「前回の一覧を表示中」のバナーが出ます。対象フォルダを変えた直後は前回の一覧を使いません。各リクエストにかかった時間は `adb logcat -s DriveApi` で確かめられます。

### 月ごとのグループとタイトル

ファイル名は `20260315_タイトル.mp4` のように、先頭の 8 桁が日付です。正規表現 `^(\d{8})_` で取り出し、`ResolverStyle.STRICT` で厳密にパースするため、「13 月」や「2 月 30 日」などは日付として扱われず、末尾の「日付不明」のグループに入ります。一覧は月ごと(例: 2026/04)にまとめ、月の降順、グループの中は日付の降順に並べます。カードのタイトルは日付プレフィックスと拡張子を除いて表示し、カードの下に日付とサイズを出します。

### サムネイル

サムネイルは同じディレクトリにある同名の `.webp` を優先し、なければ Drive が生成する `thumbnailLink` を使います。どちらも取得したあとは `cacheDir/thumbs/` に保存され、2 回目からは通信しません。取得はカードが画面にあるあいだだけ行い、高速にスクロールして画面外に出たカードの取得はキャンセルされ、表示中のサムネイルが後回しになりません。

## ストリーミング再生とキャッシュ管理

タップすると、Media3 の `CacheDataSource` を通してすぐにストリーミング再生が始まります。再生で受信したデータはそのまま `files/video_cache/`(Media3 の SimpleCache)に書かれ、同時に `CacheWriter` がまだ取得していない範囲だけをバックグラウンドで取得して、全体を保存します。再生と保存で同じデータを二重にダウンロードしません。完全に保存したファイルのメタデータ(fileId、ファイル名、サイズ、最終再生日時)は、Room の `cached_videos` テーブルで管理します。

### LRU による削除(CacheEvictionPolicy)

- 保持期間切れ: 最終再生から設定した日数(既定は 30 日)を過ぎたものを、起動時に削除します
- 容量超過: 合計が上限(既定は 10GB)を超えたら、最終再生日時の古い順に、上限を下回るまで削除します
- 再生中のファイルは常に除きます(再生中の fileId は PlaybackTracker が持っています)

この判定は純粋な関数として実装し、8 件のユニットテストで確かめています。判定するのは「起動時」「保存完了後」「設定変更後」の 3 か所です。視聴の途中でやめた部分キャッシュは、SimpleCache の側の `LeastRecentlyUsedCacheEvictor`(上限は設定値)が自動で管理する二段構えです。

### 通信量への配慮

既定では従量制でないネットワーク(Wi-Fi など)のときだけダウンロードします。判定は `NET_CAPABILITY_NOT_METERED` で行うので、従量制の Wi-Fi テザリングもブロックされます。設定で「モバイル回線でもダウンロード」を有効にできます。

## 再生とバックグラウンド再生

再生は Media3 で行います。ExoPlayer は `PlaybackService`(MediaSessionService)の中に作られ、画面の側は `MediaController` を通して接続します。この構成で、次のことができます。

- ホーム画面へ移ったり画面をオフにしたりしても、音声の再生を続ける(フォアグラウンドサービス)
- 通知とロック画面に、再生と一時停止(Media3 の標準)、停止(カスタムコマンド)を表示する
- イヤホンを抜くと自動で一時停止し、オーディオフォーカスも自動で処理する

再生画面は YouTube 風のレイアウトで、上部に 16:9 のプレイヤー、下部に概要欄(タイトル、日付、サイズ、保存状態、フォルダパス、ファイル名)を表示します。フォルダパスは一覧の取得時に全フォルダの情報から算出して持ち回るので、再生時に API を呼びません。プレイヤーの全画面ボタンで全画面(概要欄とシステムバーを隠す)に切り替えられ、全画面のときの「戻る」は全画面を解除します。縦型の動画(shorts)は画面全体に表示し、概要欄は「詳細」からボトムシートで開きます。再生画面から「戻る」と、再生は止まります。
