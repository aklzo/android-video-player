## 対象と前提

- リポジトリ: android-video-player
- パッケージ: com.aklzo.videoplayer
- minSdk 26 / targetSdk 34
- Kotlin + Jetpack Compose + Jetpack Media3 + Google Drive API

## Google 認証

- Credential Manager と AuthorizationClient で Google アカウントにサインインし、`https://www.googleapis.com/auth/drive.readonly` スコープの OAuth アクセストークンを取得する。
- 初回の起動ではサインイン(同意)画面を表示する。2 回目以降はサイレントに認証する。
- トークンが失効したとき(API が 401 を返したときなど)は、再サインインを促す UI を表示する。
- 書き込み系の API は使わない(drive.readonly の範囲に限る)。

## 対象フォルダの選択

- 初回のサインインのあと、Drive のフォルダをブラウズして動画のフォルダを選ぶ画面を表示する。
- 対象フォルダは複数選択でき、あとから追加と削除ができる。設定画面に、選択中のフォルダの一覧と「フォルダを追加」「削除」の操作を置く。
- 選んだフォルダ(ID と名前)のリストは永続化し、次回からは選び直さなくてよい。
- 一覧には全対象フォルダの配下の動画をまとめて表示する。同じファイルは重複させない。フォルダパスは「対象フォルダ名/サブフォルダ…」の形式で表示する。

## 一覧表示

- 選択フォルダの配下(サブフォルダを再帰的に含む)の `.mp4` を Drive API の `files.list` で列挙し、一覧に表示する。動画と `.webp` はサブディレクトリ単位でひとまとまりに保存されている想定で、そのまとまりより上のフォルダを選んでも、すべての動画が一覧に出る。
- 表示は YouTube のようなサムネイルのグリッドで、タップすると再生する。
- 画面の下にタブを置き、「動画一覧」(対象フォルダの配下すべて)、「プレイリスト」、「保存済み」(キャッシュへの保存を終えた動画だけ)を切り替える。保存済みタブとプレイリストタブは端末内のメタデータから組み立て、オフラインでも表示できる。
- サムネイルには、同名(拡張子違い)の `.webp` が同じディレクトリにあればそれを表示する。
  - `.webp` はその場でダウンロードし、端末内(アプリ専用ストレージ)にキャッシュする。
  - `.webp` がない場合は、Drive API の `thumbnailLink` を代わりに使う。
- 前回取得した一覧を端末に保存しておき、次の起動ではそれをすぐに表示して、裏で最新に更新する。更新中は画面の上部に細いプログレスバーを表示する。
- オフラインのときや API が失敗したときは、前回の一覧があれば表示を続け、「前回の一覧を表示中」と知らせる。前回の一覧もなければ、エラーと再試行ボタンを表示する。
- ディレクトリフィルター: 一覧の上部のチップで、対象フォルダの直下のサブディレクトリ名(例: shorts / streams / videos)ごとに表示を絞り込める。「すべて」で絞り込みを解除する。分類はフォルダパスから動的に決め、ディレクトリ名をコードに書き込まない。

## プレイリスト

- 名前を付けたプレイリストを作成、削除できる。
- 動画一覧タブと保存済みタブのカードを長押しすると、プレイリストに追加できる(追加先を選ぶか、新しいプレイリストを作る)。
- プレイリストタブに一覧(名前と件数)を表示し、タップすると中身を追加順に表示する。
- プレイリストの中の動画はタップで再生し、長押しでプレイリストから削除できる。
- プレイリストの内容(動画のメタデータ)は Room に保存し、オフラインでも表示できる。

## 月ごとのグループとタイトル

- ファイル名は先頭に `yyyyMMdd` 形式の日付とアンダースコアを持つ(例: `20260315_タイトル.mp4`)。
- 正規表現 `^(\d{8})_` で日付を取り出し、日付として正しくない値(13 月、32 日など)は日付として扱わない。
- 一覧は日付の降順に並べ、月ごと(例: `2026/04`)にまとめて表示する。
- 日付を取り出せないファイルは、「日付不明」のグループとして末尾に表示する。
- 一覧のタイトルは日付プレフィックスと拡張子を除いて表示する(例: `20260315_タイトル.mp4` → `タイトル`)。日付などのメタ情報は再生画面の概要欄に表示する。

## 再生(ストリーミングとバックグラウンド保存)

- 一覧でタップすると、すぐにストリーミング再生を始める(`files.get?alt=media`)。
- 再生と並行して、動画全体をバックグラウンドでアプリ専用ストレージの `files/video_cache/` に保存する。再生で受信したデータは保存にも使い、同じデータを二度取得しない。
- 保存中は再生画面に進捗を表示する。
- 保存済み(キャッシュが有効)の動画は、オフラインでもすぐに再生できる。
- 一覧に、キャッシュ済みであることを示す印を表示する。

## 再生画面

- 横型の動画は YouTube のようなレイアウトで、上部に動画プレイヤー(16:9)、下部に概要欄を置く。プレイヤーの全画面ボタンで全画面に切り替えられ、全画面のときの「戻る」は全画面を解除する。
- 縦型の動画(shorts)は YouTube Shorts のように画面全体に表示する。概要欄は表示せず、画面下の「詳細」から、横型の動画の概要欄と同じ内容をボトムシートで開ける。縦型かどうかは shorts ディレクトリにあるかどうかを初期値とし、実際の映像サイズ(縦が横より長い)で確定する。
- 概要欄にはタイトル(日付と拡張子なし)、日付、フォルダパス(選択フォルダからの相対パス)、ファイル名、サイズ、保存状態(保存済み/保存中◯%/未保存)を表示する。
- プレイヤーの左上に、一覧へ戻る矢印ボタンを常に表示する。
- 再生、一時停止、シークバーに対応する。

## バックグラウンド再生

- アプリを離れても、画面をオフにしても、音声の再生を続ける。
- `MediaSessionService` を使い、通知の再生コントロール(再生/一時停止/停止)とロック画面の表示に対応する。

## キャッシュ管理(LRU)

- キャッシュの合計が容量の上限を超えたら、最終再生日時の古いものから削除する。上限の既定値は 10GB で、設定画面で 5GB / 10GB / 20GB / 50GB から変えられる。
- 最終再生から 30 日(設定で 7 日 / 30 日 / 90 日 / 無期限から変えられる)を過ぎたファイルは、起動時に削除する。
- 再生中のファイルは削除しない。
- 設定画面に、いまのキャッシュ使用量と、手動で全削除するボタンを置く。
- キャッシュのメタデータ(fileId、最終再生日時、サイズ)は Room で管理する。

## 通信量への配慮

- 動画のダウンロードは既定では Wi-Fi に接続しているときだけ許可する。設定でモバイル回線でも許可できる。

## 設定画面

- 対象フォルダの変更
- キャッシュ容量の上限(5/10/20/50GB)
- キャッシュの保持期間(7 日/30 日/90 日/無期限)
- モバイル回線でのダウンロードの許可(ON/OFF)
- キャッシュ使用量の表示と全削除ボタン
